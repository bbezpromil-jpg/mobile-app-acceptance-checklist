# Правила работы с репозиторием

## Назначение

Публичный набор Markdown-документов для приёмки мобильных приложений. Содержит README и шаблоны. Основная ветка — main. Здесь нет приложения, зависимостей, сборки или деплоя.

Сохранять практическое содержание, проверяемые критерии и относительные ссылки. Не добавлять вымышленные результаты клиентов, рейтинги, массовые рекламные ссылки или закрытые сведения из других проектов. Учебные примеры явно обозначать.

Перед публикацией проверять Markdown, согласованность статусов, относительные ссылки и отсутствие секретов. Не создавать тесты, зеркалящие формулировки документов.

## GitHub Actions: экономия по умолчанию

Автоматические workflows и расписания для этих документов не настроены и не требуются. Runner не подключён; метки, доступ и общая очередь не проверялись. Сборка и серверная публикация отсутствуют. Не добавлять фиктивный CI ради отметки.

До первого реально необходимого workflow:
- Проверить self-hosted runner с доступом именно к этому репозиторию и записать реальные метки, очередь, ограничения ресурсов и команды проверки.
- Все jobs направлять только на проверенный self-hosted runner. Не добавлять fallback на GitHub-hosted, включая ubuntu-latest, ubuntu-slim, Windows или macOS, без явного указания владельца.
- Пока runner не подключён, продолжать подготовку без автоматических запусков. Не переносить метки или доступ других репозиториев по предположению.
- На общем сервере сериализовать тяжёлые сборки между репозиториями, ограничить ресурсы и очищать временные файлы. Не запускать недоверенный код внешних PR на постоянном runner с доступом к production.
- Запускать по необходимым событиям, не дублировать проверки и не добавлять cron без задачи. Отменять устаревшие проверки; безопасную публикацию сериализовать без прерывания.
- Отбирать изменения по фактическим входам проверки; при неизвестной базе diff выполнять необходимую проверку. Документация является продуктом этого репозитория.
- Ограничивать время и повторы, проверять входные данные до AI или тяжёлой обработки. Временные диагностические артефакты хранить обычно 3 дня.
- Сохранять необходимые проверки и возможность отката. Не считать пропущенную обязательную проверку успешной.
- Не менять тарифы и денежные бюджеты без запроса. Различать число запусков, измеренные минуты и фактические расходы.

## Если позднее потребуется SSH

В текущем репозитории SSH не используется. До подключения любого SSH-пути проверить цель, пользователя, один метод входа и закреплённый host key. Использовать постоянный общий журнал отказов и очередь авторизации для этой цели, keepalive и ограниченные сроки. После отказа или неизвестного результата остановить повторные входы до разбора. Не перебирать ключи, не добавлять fallback, не отключать проверку host key или firewall и не сбрасывать журнал для обхода отказа. Проверить наличие защитного модуля в каждом checkout и выполнить один необходимый read-only контрольный запуск. Не публиковать адреса инфраструктуры или секреты в этом репозитории.
