## Сценарии

При отсутствии управляемого отказа или доступа к серверному подтверждению ставьте `Blocked` с причиной. Не подменяйте проверку потери ответа простым отключением интернета до нажатия.

| ID | Условие и действие | Ожидаемый результат по согласованному контракту | Фактический результат / серверные ID / доказательство | Статус |
|---|---|---|---|---|
| NET-01 | Отключить сеть до «Отправить» и выполнить действие. | Интерфейс различает черновик/очередь и серверное создание. Не показывает неподтверждённый заказ как принятый. | | Not run |
| NET-02 | При медленном ответе дважды нажать «Отправить» для одной операции. Затем намеренно оформить второй самостоятельный заказ. | Первому действию вместе с его повтором соответствует одна заявка. Новый самостоятельный заказ получает отдельный серверный ID и не объединяется с первым. Подтверждено число записей на сервере. | | Not run |
| NET-03 | Контролируемо прервать запрос до его применения сервером; затем восстановить связь. | Зафиксировано, что исходное действие не применялось. Предусмотренное восстановление создаёт одну заявку, без ложного подтверждения до ответа. | | Not run |
| NET-04 | Дать серверу создать заявку, потерять ответ и выбрать восстановление после тайм-аута. | Показана исходная заявка с тем же серверным ID; повтор не создаёт вторую. Неизвестный результат до восстановления обозначен корректно. | | Not run |
| NET-05 | В состоянии неизвестного результата закрыть и заново запустить приложение, затем вернуть сеть. | Состояние восстанавливается по требованиям; судьба исходной операции устанавливается. Нет незаметного нового заказа. | | Not run |
| NET-06 | Во время ожидания сменить Wi-Fi на мобильную сеть, затем вновь открыть список и карточку. | Интерфейс сверяется с сервером; карточка и список относятся к одному актуальному заказу. Само появление сети не объявляется успехом. | | Not run |
| NET-07 | Оставить операцию пользователя A в ожидании, выйти и войти как B. | B не видит данные A; очередь A не выполняется с правами B. Дальнейшая судьба операции A соответствует согласованному правилу. | | Not run |
| NET-08 | Во время восстановления получить ошибку авторизации либо достичь лимита повторов. | Автоматические попытки прекращаются по контракту; показаны понятное состояние и следующий шаг. Не создаются новые операции для обхода лимита. | | Not run |
| NET-09 | Превысить срок актуальности ожидающей операции или распознавания повторов; затем вернуть сеть. | Устаревшее действие не исполняется неожиданно. Неизвестный результат разрешается по контракту, без безусловного повторного создания с новым ключом. | | Not run |
| NET-10 | Отменить локальное ожидание при двух вариантах: сервер ещё не принял заявку / сервер уже принял её с потерей ответа. | Интерфейс различает прекращение локальной отправки и подтверждённую отмену на сервере. Состояние и число заказов проверены для обоих вариантов отдельно. | | Not run |

Для проверок повторов, если это предусмотрено контрактом, отдельно воспроизведите одновременные запросы с одним идентификатором операции. Несогласованность данных или сроков распознавания сначала оформляйте как открытый вопрос.

## Статусы

- `Not run` — проверка не выполнялась.
- `Pass` — заранее записанный ожидаемый результат подтверждён.
- `Fail` — результат расходится с ожиданием.
- `Blocked` — не хватает условия или доказательства; причина указана.

Ведите отдельный экземпляр для каждой платформы/конфигурации. Учебные ожидания адаптируйте до запуска. Неприменимые сценарии перечислите ниже с причиной, не отмечая их как `Pass`.
