# Матрица приёмки push-уведомлений

Заполните приватную рабочую копию по [руководству](../guides/notifications-acceptance.md). Ниже — 14 учебных сценариев, а не результаты испытаний. Исходный статус каждой строки — `Not run`. Уточните критерии под продукт до проверки; создавайте отдельную копию для каждой платформы и конфигурации.

## Паспорт проверки

| Поле | Значение |
|---|---|
| Продукт, версия и номер сборки | Заполнить |
| Серверное окружение и версия | Заполнить |
| Устройство, ОС, целевой SDK для Android | Заполнить |
| Поставщик уведомлений и тип сообщения | Заполнить без секретов |
| Сеть и ограничения устройства | Заполнить |
| Разрешения, звук, предпросмотр | Заполнить |
| Тестовые пользователи А и Б, их роли | Условные обозначения |
| Тестовые заявки А и Б | Условные обозначения |
| Требования и согласованное окно ожидания | Заполнить |
| Дата, время, часовой пояс, проверяющий | Заполнить |

## Правило одного события

| Поле | Согласованное правило |
|---|---|
| Событие и источник его подтверждения | Заполнить |
| Адресат и условия включения в получатели | Заполнить |
| Состав текста и допустимые сведения | Заполнить |
| Срок хранения сообщения и срок актуальности действия | Заполнить раздельно |
| Повтор, группировка и порядок разных событий | Заполнить |
| Показ при открытом приложении и в фоне | Заполнить раздельно |
| Экран после нажатия, проверка текущего состояния и доступа | Заполнить |
| Поведение без сети, без сессии и при недоступной записи | Заполнить |

## Сценарии

Перед каждой строкой восстановите её исходное состояние. Проверяйте только согласованные тестовые устройства, учётные записи и записи. В колонке доказательства используйте время, условные идентификаторы и приватные ссылки; значения ключей, токены устройств и личные данные туда не вставляйте.

| ID | Условие и действие | Ожидаемый результат для согласования | Факт и доказательство | Статус |
|---|---|---|---|---|
| N01 | Чистая установка в согласованной конфигурации; дойти до объяснённого запроса и разрешить уведомления; создать событие. | Запрос соответствует платформе и требованиям; сообщение приходит нужному пользователю в согласованном окне. | Не проверено | Not run |
| N02 | На первом запросе отказать; создать событие и вручную открыть список заявок. | Отказ не объявляется разрешением; согласованные основные функции и актуальные данные доступны; интерфейс объясняет состояние уведомлений. | Не проверено | Not run |
| N03 | После разрешения отключить уведомления в настройках ОС; вернуться в приложение и создать новое событие. | Интерфейс учитывает текущие настройки и не обещает активный показ; основные функции работают по требованиям. | Не проверено | Not run |
| N04 | Оставить приложение открытым на согласованном экране; создать событие для текущего пользователя. | Обновление, баннер или сообщение внутри приложения соответствуют выбранному варианту; лишних повторов нет. | Не проверено | Not run |
| N05 | Свернуть приложение; создать событие; нажать полученное уведомление. | Нужный адресат открывает нужную заявку с текущими данными; возврат ведёт в согласованный раздел. | Не проверено | Not run |
| N06 | Завершить процесс согласованным способом; получить сообщение и открыть его. | Запуск восстанавливает маршрут; при необходимости выполняется вход; открывается разрешённая актуальная карточка либо понятное состояние недоступности. | Не проверено | Not run |
| N07 | По согласованной процедуре повторно отправить одно тестовое событие. | Повтор и группировка соответствуют правилу; лишняя заявка, назначение или иная бизнес-операция не создаются. | Не проверено | Not run |
| N08 | Получить сообщение о назначении; отменить заявку до нажатия; открыть старое уведомление. | Показана отменённая заявка либо согласованное состояние; прежнее действие не выполняется; серверное состояние не меняется от открытия. | Не проверено | Not run |
| N09 | Отключить сеть; создать событие; восстановить связь до заданного срока истечения. | В согласованных условиях сообщение появляется в установленном окне; открытие показывает текущие данные. | Не проверено | Not run |
| N10 | Отключить сеть до отправки; создать событие; восстановить связь после установленного срока хранения сообщения. | Поведение соответствует настройке истечения; просроченный призыв не предлагается как доступное действие; ручное открытие показывает актуальную запись. | Не проверено | Not run |
| N11 | Подготовить два события одной заявки и согласованно воспроизвести получение более старого после нового. | Порядок показа соответствует правилу; старое событие не возвращает карточку в прежнее состояние и не повторяет завершённую операцию. | Не проверено | Not run |
| N12 | Получить уведомление А; выйти из А, войти в Б; создать новое событие для А и нажать оставшееся старое сообщение А. | Б не получает закрытые сведения А и не открывает его заявку; текущий доступ проверяется после входа; видимые остаточные сообщения обработаны по правилу. | Не проверено | Not run |
| N13 | До нажатия дождаться истечения тестовой сессии либо отозвать доступ к записи согласованным способом; открыть уведомление. | Предусмотрен вход или понятный отказ; закрытые сведения не раскрываются, запрещённое действие не выполняется. | Не проверено | Not run |
| N14 | Заблокировать экран; отправить сообщение с подготовленными вымышленными данными при записанных настройках предпросмотра. | В заголовке, тексте и предпросмотре отображаются только согласованные поля; после разблокировки переход учитывает текущую сессию. | Не проверено | Not run |

## Как оформить наблюдение

| Поле | Значение |
|---|---|
| ID сценария и идентификатор тестового события | Заполнить |
| Момент события на сервере | Время и часовой пояс либо «не наблюдалось» |
| Момент принятия отправки поставщиком | Время и источник либо «не наблюдалось» |
| Момент показа на устройстве | Время либо «показа не было в согласованном окне» |
| Момент открытия и показанная запись | Заполнить |
| Ожидаемое и фактическое поведение | Заполнить раздельно |
| Безопасные доказательства | Приватные ссылки без секретов |
| Дефект или блокировка, следующий шаг | Заполнить при необходимости |

`Pass` ставится после подтверждения согласованного результата. `Fail` означает наблюдаемое расхождение. `Blocked` требует конкретной причины и условия продолжения. Невыполненная проверка остаётся `Not run`; неприменимые пункты перечисляются ниже с обоснованием и не превращаются в успешные.

## Итог

- Проверенные платформы, сборки и конфигурации: заполнить.
- Неприменимые сценарии и согласовавший исключение: заполнить.
- Невыполненные проверки, дефекты и блокировки: заполнить.
- Повторная проверка после исправлений: версия, дата, сценарии, результат.
- Решение по согласованному объёму и оставшиеся ограничения: заполнить.
